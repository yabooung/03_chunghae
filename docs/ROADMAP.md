# 상품화 로드맵

지금 상태: 캐주얼하게 끝까지 즐길 수 있는 웹 프로토타입. 난이도 셋(바람·풍랑·태풍), 모바일 화면 대응, 선장 셋의 본 이야기와 결말 11개, 사전 117항목, 프롤로그·조건형 안내. 재미는 만든 사람만 확인했다.

## 0. 끝낸 것 (2026-10 개선 목록에서)
- 선장별 상납 이름·호칭 토큰, 명성 HUD와 이유 알림, 상대 연도, 결말 에필로그·마지막 선택 글·염장 분기 재설계, 프롤로그 3쪽 → 第一幕 → 안내 순서, 첫 화면 훅·저장 덮어쓰기 확인, 사전 z-index.
- 상납 곡선 상한(배 칸 기준)·세 해 결말·첫 실패 빚(뱃삯은 남긴다)·계절 결산 표·상납 예측, 숨은 항구 첫 입항 1회 프리미엄, 의뢰 허점, 두목 수배 tier 게이트, 입항 카드 실제 값, 도모 시작 경제, 관아·지분·배 두 종, 역풍 기다리기, 경주.
- 모바일 HUD·지도 가림·메뉴 가림·선원 쪽지, 초점 가두기, 글꼴 분할 적재(3G 첫 그림 0.7초), 도움말 창, 움직임 줄이기 메뉴.

## 1. 외부 플레이테스트 (가장 먼저, 가장 싸다)
- Pages 빌드 링크를 10~20명에게 돌린다.
- 볼 것: 첫 상납 전 이탈률, 한 판 길이, 막을 어디까지 보는지, 두 번째 판 시작 여부, 난이도 선택 비율과 풍랑 첫 해 생존.
- 필요하면 플레이 기록(이탈 지점·판 길이)을 남기는 기능을 넣는다.

## 2. 핵심 하나 정하기
테스트 반응을 보고 장사 / 탐험 / 이야기 중 무엇을 중심축으로 깊게 팔지 정한다.
로그라이트(짧은 판 반복)인지 긴 캠페인인지도 이때 정한다 — 콘텐츠를 어디에 쌓을지가 달라진다.

## 3. 구조 정리
- 콘텐츠(항구·사건·퀘스트·본 이야기)를 `data/`로 빼서 코드 없이 늘릴 수 있게 한다.
- core.js를 기능별 모듈로 나눈다.

## 4. 버티컬 슬라이스
아트(인물 초상·항구·배)와 사운드까지 들어간 30분짜리 완성본. 2D 해도 스타일을 정체성으로 유지.

## 5. 상점 페이지
Steam 상점 페이지 + 찜하기 수로 시장 반응 확인 → 본격 제작 여부 결정.
